# exp_005 — Hypothesis: Visual Studio builds the all-C core and it is wire-compatible

**Status:** hypothesis written before the formal experiment run.

## What we expect

1. `scripts/build_c.bat` finds Visual Studio via `vswhere`, initializes
   `vcvars64.bat`, and compiles the C protocol library and tests with MSVC
   `/W4 /WX` (warnings are errors) with zero warnings.
2. All C unit tests pass: header layout (16/88/16 bytes), byte-identical
   round-trip for JPEG/WAVE/unknown types, and rejection of negative,
   truncated and oversized payloads.
3. A capture generated by the **C encoder** (`capture_writer.exe`) is accepted
   by the existing Rust/Harness dissector and re-encoded byte-identically,
   showing both implementations agree on the wire format.

## Why

The user directed an all-C implementation and confirmed Visual Studio is
available. This is the first evidence that the C core is real, compilable on
the required toolchain and compatible with the protocol already documented
from Teleport source. If the C and Rust implementations disagree on bytes,
every later parity claim would be suspect.

## What would prove us wrong

- MSVC warnings/errors under `/W4 /WX`.
- Any failing C unit test.
- The Rust dissector rejecting the C-generated capture or producing a
  different byte stream on re-encode.

## Method

- `cmd /c scripts\build_c.bat` (MSVC build + C tests).
- `build\c\capture_writer.exe exp_results\c-wire.bin 4`.
- `wormhole-harness dissect` with a config pointing at `c-wire.bin`.
- Compare the C-generated bytes with the dissector's re-encode (the dissector
  asserts byte identity itself).
